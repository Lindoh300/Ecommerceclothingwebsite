# AGENTS.md

Guidance for AI coding agents and new contributors working in this repository.

## Project overview

**4Nguru The Brand Online** is a South African clothing storefront. Prices are in Rand (R). The app was exported from Figma Make. It is a client-side React app: products and the cart live in the browser, and checkout opens a WhatsApp chat with a pre-written order. There is no backend in use yet (see [docs/ISSUES.md](docs/ISSUES.md)).

Known problems are tracked in [docs/ISSUES.md](docs/ISSUES.md). Planned work is in [docs/ROADMAP.md](docs/ROADMAP.md). Release notes are in [docs/changelog.md](docs/changelog.md).

## Stack

- Vite 6 with the React plugin and the Tailwind plugin (`@tailwindcss/vite`).
- React 18 with TypeScript.
- React Router 7. Routes are defined with `createBrowserRouter` in `src/app/routes.tsx`.
- Tailwind CSS 4.
- shadcn/ui components built on Radix, in `src/app/components/ui/`.
- `lucide-react` for icons, `sonner` for toasts.

## Commands

```bash
npm i            # install dependencies
npm run dev      # start the Vite dev server
npm run build    # production build (vite build)
```

There are no test, lint or typecheck scripts. Verify changes with `npm run build`, then open the affected pages in `npm run dev` and check them in the browser.

## Architecture and data flow

- **Products** are read and written through `src/app/utils/storage.ts`. Sample products are seeded into `localStorage` under `clothing_store_products` the first time a browser loads the site. Admin edits in `/admin` only change that browser's copy (see [#1](docs/ISSUES.md#1-product-data-is-per-browser-not-shared)).
- **Cart** is stored in `localStorage` under `clothing_store_cart` through the same module. Each cart item copies the whole product object (see [#3](docs/ISSUES.md#3-uploaded-images-can-exhaust-localstorage)).
- **Cart change event:** `addToCart` in `storage.ts` dispatches a `cartUpdated` window event, as do the components that change the cart: `Cart.tsx` and `ProductDetail.tsx`. `Header.tsx` listens for `cartUpdated` to refresh the cart badge. When you change the cart in a new place, dispatch this event too.
- **Checkout** is in `handleWhatsAppCheckout` in `Cart.tsx`. It builds the order text and opens WhatsApp. The cart is not cleared until the customer confirms in the "Did you send your order?" panel (see [#6](docs/ISSUES.md#6-no-payment-or-order-record-at-checkout)).
- **Stock** is enforced client-side only. `getCartQuantityForProduct(productId, excludeIndex?)` counts a product's quantity across all sizes and colours in the cart, and `getAvailableStock(productId, fallback)` returns its stock. `addToCart` and `updateCartItem` return `boolean` and refuse to go over stock, so callers must handle `false` with a toast. Stock is still never decremented (see [#5](docs/ISSUES.md#5-stock-is-never-decremented-or-enforced)).
- **Contact details** (WhatsApp number, phone, email, social links) live only in `src/app/config/shop.ts`. Import them from there (see [#8](docs/ISSUES.md#8-contact-details-are-hardcoded-in-several-places)).
- **Admin** is at `/admin`. The password check is client-side and the session flag is in `sessionStorage` (see [#2](docs/ISSUES.md#2-admin-authentication-is-not-secure)). Do not build new features on it.
- **Supabase** has a scaffolded edge function with a single `/health` route. Nothing in `src/` calls it yet (see [#7](docs/ISSUES.md#7-supabase-backend-is-scaffolded-but-unused)).

## Design system rules (Prism)

The Prism design system is in place, and every page uses it. The rules below are its conventions.

- Use Prism tokens and classes, not raw values. Colours come from the theme tokens: `--prism` (accent `#ff4081`), `--ink`, `--paper`, the greys `--b5`, `--b10`, `--b60`, and the generative palette `--g1` to `--g6`. In Tailwind, use `bg-prism`, `text-ink`, `border-b10` and similar classes.
- Fonts: `font-display` (Asul) for headings, `font-sans` (Cabin) for body text, `font-mono` (IBM Plex Mono) for labels and prices, `font-hand` for handwritten accents.
- Use the utility classes in `src/styles/prism.css`: `.display`, `.h-sec`, `.h-mid`, `.hand`, `.micro`, `.linkr`, `.ticker`, `.goo`, `.cta`.
- Display headings are uppercase.
- Corners are square or nearly square. The one exception is the `.cta` button, a black pill shape (`border-radius: 999px`) ported from the template. Do not add other rounded pill shapes.
- The `.display` and `.micro` classes in `prism.css` are unlayered, while Tailwind utilities sit in layers. So `.display` and `.micro` override Tailwind text-size utilities on the same element. Do not expect a `text-*` class to win on those elements.
- Do not introduce new colours outside the theme tokens. If you need one, add a token in `theme.css` first.
- The original 4Nguru logo in the header is kept as the brand mark: the round logo image, then the multicolour letters 4-N-g-u-r-u (Tailwind `text-yellow-500`, `text-green-500`, `text-blue-500`, `text-red-500`, `text-purple-500`, `text-yellow-500`) followed by "The Brand Online". Do not restyle it. It is the one exception to the rule against colours outside the tokens.
- Reuse the components in `src/app/components/prism/` (`GooFilters`, `GooArt`, `Ticker`, `ProductImage`) rather than writing new ones. `GooFilters` is mounted once in `Root`. `ProductImage` falls back to `GooArt` when a product has no image.
- Honour `prefers-reduced-motion`. Disable or reduce animations, tickers and transitions when it is set.

## Conventions

- Use named function components: `export function Cart() { ... }`.
- Style with Tailwind utility classes. Avoid inline `style` objects unless a value is computed at runtime.
- Build UI from the shadcn/ui primitives in `ui/` where one exists. Add a new `ui/` component only through the shadcn CLI or by copying an existing pattern.
- Keep files small. Split a component when it grows past a screenful of logic, and move shared helpers into `utils/`.
- Use relative imports, matching the existing code (for example `../utils/storage`). The `@` alias to `src/` exists in `vite.config.ts` but is not used.
- Use `toast` from `sonner` for user feedback. Do not use `alert()` in new code.

## Guardrails

- Do not edit `utils/supabase/info.tsx`. It is generated.
- Do not remove the `react()` or `tailwindcss()` plugins from `vite.config.ts`. Figma Make requires them.
- Keep the docs in sync with the code:
  - Add a line to `docs/changelog.md` under `[Unreleased]` for every user-visible change.
  - Tick off items in `docs/ROADMAP.md` when they land, and update their status.
  - Check `docs/ISSUES.md` before you start on a known problem, and link to it in commit messages or PRs.
- Do not commit secrets. The Supabase anon key in `info.tsx` is public by design; service keys are not.
- Do not add new public routes or links to `/admin`.
- Never hardcode contact details; import from `src/app/config/shop.ts`.

## Testing and verification

There are no automated tests. For every change:

1. Run `npm run build` and confirm it passes.
2. Run `npm run dev` and open each affected page: the home page, a category page, a product page, `/cart`, and `/admin` if you touched it.
3. Check the cart badge in the header updates after adding or changing items.
4. Check the layout at phone width and with `prefers-reduced-motion` on.
